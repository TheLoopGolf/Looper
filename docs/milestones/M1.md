# M1 — Foundation: report

## What was built

- **Monorepo** (pnpm workspaces): `apps/web`, `apps/desktop` (Tauri 2), `packages/{core,render,ui,pixel-wasm,ai,plugins}`.
- **Document model** with 7 layer types, groups, masks/effects slots, guides, selection, metadata; immutable updates.
- **Tile store**: sparse copy-on-write 256×256 grids shared across history, duplicates and files.
- **Command API**: registry with schema validation and agent tool generation (`toAgentTools`), 14 layer/pixel
  commands (create, delete, duplicate, move/reorder, rename, visibility, lock, opacity, fill, blend mode,
  group, ungroup, fill rect, place image), invertible patches.
- **History**: undo/redo, jump-to-state, slider coalescing, grouped entries with actor badges (agent runs undo
  in one step and expand to their steps), cancel-group for stopped runs, 200-entry cap.
- **Renderer**: WebGPU primary, WebGL2 and CPU fallbacks, 26 blend modes, isolated + pass-through groups,
  opacity/fill, dirty-tile tracking, visible-first time-budgeted compositing, mipmapped display tiles,
  device-lost fallback to the next backend.
- **UI**: menu bar, tool strip (move/hand/zoom), document tabs, canvas with wheel/pinch zoom-at-cursor,
  space/middle/hand panning, Layers panel (tree, drag-and-drop reorder/into groups, inline rename, visibility,
  lock, blend mode, opacity, fill, keyboard navigation), History panel, status bar (zoom, size, cursor,
  backend/fps), New Document dialog with presets, toasts, dark/light themes, keyboard shortcuts.
- **Files**: open PNG/JPEG/WebP/GIF/BMP/AVIF (dialog or drag-and-drop), `.cnva` save/open with thumbnail and
  history metadata, export PNG/JPEG/WebP; File System Access API on web, Tauri dialog/fs on desktop.
- **Rust**: `canvas-pixel` crate (downsample, premultiply) building for native and wasm32.
- **Contracts for later milestones**: `AIProvider` / capability I/O types, agent definition + approval modes,
  plugin manifest with validation and plain-language permission descriptions.

See the README quick start. Tests: `pnpm test`, `pnpm test:e2e`, `pnpm bench`, `cargo test` in `packages/pixel-wasm`.

| Suite | Result |
| --- | --- |
| Vitest (core, render, plugins) | 81 / 81 passed |
| CPU golden images (26 blend modes + 3 group scenes) | exact match to stored goldens |
| Playwright app flows (layers, undo/redo, history groups, errors, drag-and-drop, pan/zoom, .cnva round-trip, PNG open, PNG/JPEG export) | 8 / 8 passed |
| GPU vs CPU golden images, WebGPU and WebGL2 | 4 / 4 passed, max diff 1 LSB |
| Rust (`canvas-pixel`) | 3 / 3 passed; wasm32 release build 20 KB |
| Memory: 7 × (100 edits, 100 undo, 100 redo, branch) on a 2048² layer | heap growth < 30 MB (no leak; each cycle allocates ~100 MB) |

### Acceptance criterion: 6000×4000, 20 layers, 60 fps pan/zoom, 100-step undo/redo without leaks

`pnpm bench` (headless, **software** GPU — not representative of a mid-range laptop):

| Backend | Full composite (384 tiles × 20 layers) | Pan/zoom frame p50 | p95 | CPU per frame |
| --- | --- | --- | --- | --- |
| WebGL2 | 9.1 s | 16.7 ms (60 fps) | 66.7 ms | 0.3 ms |
| WebGPU | 32.0 s | 33.4 ms (30 fps) | 50.1 ms | 1.8 ms |

Pan/zoom only redraws cached tiles, so frame cost is independent of layer count; the remaining time is
SwiftShader rasterization. **The 60 fps target still has to be confirmed on real GPU hardware** (run
`pnpm bench` headed); undo/redo without leaks is verified by the unit test above.

## Known gaps

- Desktop shell is scaffolded (config, capabilities, icons, native file platform) but **not compiled here**:
  the container lacks WebKitGTK. Build it on a machine with Tauri prerequisites.
- Brush latency target (< 16 ms) is untestable until painting lands in M2.
- Masks, clipping, adjustment/text/shape layers exist in the model but are not rendered yet (M2).
- Tile seams can appear at strong zoom-out with linear filtering (each tile filters in isolation).
- Opening images goes through a 2D canvas, which premultiplies internally; very low-alpha pixels lose precision.
- Large exports/saves run on the main thread (with yielding); moving them to a worker is planned.
- Color management: documents are tagged sRGB/Display P3, but no conversion is done yet.
- Headless-test caveat: Chromium needs Vulkan SwiftShader flags for WebGPU presentation, and
  `page.screenshot()` of a WebGPU canvas kills the GPU instance in this environment (harness captures
  frames with `toDataURL` in the draw task instead).
